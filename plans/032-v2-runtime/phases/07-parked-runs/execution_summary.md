Learned:
- Expiry timing: card expiry emits no bus event; the deadline timer polls `get()` `expiry_polls + 1` times spaced `expiry_poll_s` (3 × 5 s) and then rejects the card itself with reason "ttl elapsed" (`decided_by="system"`, muted so its own `approval.decided` echo is discarded). On an engine whose sweeper lags more than 15 s the plugin rejects first.
- `filter=` is top-level equality on a dict payload; a non-dict payload never matches; the subscription is exact-name (`bus.subscribe(name, handler)`), the handler resumes inline and the run task is spawned from `_resume` — the bus handler returns before the segment runs.
- Every resume path (`approval.decided`, bus event, timer, `reconcile`) goes through `ParkService._resume`, which re-reads the row and returns when it is no longer `parked` (test 14) — a cancelled or already-resumed run is never driven twice.
- The sqlite single-connection hazard is real for the existing `test_subtask_parent_child_rows_and_cycle_guard_across_restart` (see Results): two runs resumed concurrently on one in-memory connection can lose one run's uncommitted journal insert to the other's rollback. The parked tests avoid concurrent DB traffic under a running task by design.
- Orphan-turn behaviour without luna/02 was not observable with fakes (no core `approval.decided` → agent turn path in the plugin suite); the plugin side is prepared (payload `kind == "playbook_effect"`, `conversation_id == run.report_to`), the core-side skip is luna/02's blocked guard.
- Not handled (recorded for plugin/08, Risks 10): a child run parking inside `ctx.subtask` — `_effect_subtask` still fails the parent's effect for any child status other than `done`.
