## Learned

- `_create_run` stamps `playbook_version = live_version or playbook.version`, and `_pb()` test playbooks have `version=1`, `live_version=0` → every resume test must insert a `PlaybookVersion` row (`_save` helper); a run whose version row is gone fails loud as `VersionMissing` (extra test).
- The in-memory `sqlite+aiosqlite://` engine hands every session the same connection (StaticPool): a test that polls the journal table while the run task is writing interleaves its reader's ROLLBACK with the writer's transaction and can undo the writer's commit. The gather test observes `playbook.step.completed` events on the bus instead of polling the DB under a live run; production Postgres has no such hazard, but any future test that reads the DB concurrently with a running v2 task must do the same.
- `asyncio.gather(return_exceptions=True)` returns a non-`KeyboardInterrupt`/`SystemExit` `BaseException` as a value, and `SegmentLoop._gather` re-raises it in argument order — a death inside one gather branch leaves the other branches' rows exactly as they settled (`done`), which is what makes "gather across a restart" reconcile only the lost row.
- `wake_on_complete` is set only by agent_tools; the payload-parity test stamps it on the row directly.
