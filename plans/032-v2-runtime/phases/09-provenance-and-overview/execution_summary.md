## Learned

- The five-key envelope is derived from the RUN ROW for `_status`/`_runs_read` (`is_test or trigger == "agent-candidate"` → `candidate_test_run`/`candidate`, else `real_run`/`live`) and from the call for `_run` (`real_run`/`live`), `_run_candidate` (`candidate_test_run`/`candidate`), `_dry_run` (`dry_run`; role `candidate` / `live` (== `versioning.live_version_of`) / `historical`; `run_id` null). A candidate test run stays `candidate_test_run` after its version is promoted — the historical truth, never re-derived from pointers.
- Parked result at exit (dojop/02 contract): `{kind: "real_run", side_effects: true, version: <live>, version_role: "live", run_id, playbook, status: "parked", approval_id, message: "run <id> waiting on owner card #<uuid> — tell the user; nothing to poll. playbook_overview(name='<name>') is the truth surface — read it before describing this playbook's state.", next}` — `status == "parked"` detection unchanged. Refused stays `{status: "refused", playbook, reason}` (3 keys). `playbook_overview` and `{error}` results carry no envelope.
- `_overview` derives `pending_approvals` from parked rows (`parked_on.kind == "approval"`) merged by id with `ctx.approval.list_pending()` — luna's `ApprovalRequest` (`luna/luna/approval/contract.py`) fields `id`, `kind`, `payload`, `requested_by_plugin`; the plugin's cards key the playbook as `payload["name"]` (`playbook_change`) or `payload["playbook"]` (`playbook_effect`, `playbook_run`). A missing or failing `list_pending` yields the row-derived list only.
- `runs_of_live_since_publish` counts non-test, non-`agent-candidate` rows of the live number regardless of status — a parked real run counts (it is a run of live), a failed one too; the name promises "since publish" and the count is per version number, which is equivalent while versions are never re-published under the same number (`test_v2_live_version_invariant.py`).
- Default `agent_autonomy` for a fresh propose is `agent_must_confirm`; the overview fixture had to say so.
- Skill budgets are tight: v1 body has 9 bytes of headroom (12279/12288), v2 374 (5770/6144). plugin/11's prompt edits must re-check both.
- luna side: the 007.009 suite pins the v1 tool contract literally (`created`, `done`); each phase that changes a v1-visible tool result adds a red there until luna/04 rewrites those pins. Two now.
