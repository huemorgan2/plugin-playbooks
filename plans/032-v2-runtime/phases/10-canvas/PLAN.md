## Goal

A python (v2) playbook has a graph on the same ReactFlow canvas a pblang playbook has, derived on the server from the code: one step node per `ctx` call site (id = the checker's call-site id, node id `step-<id>`), `if`/`for`/`while` containers drawn like today's `condition`/`loop` nodes, `try` drawn as a new `error_boundary` node, the code between effects collapsed into new `compute` nodes, triggers as positional `trigger-<n>`. A run overlays the canvas from its journal: every journal entry lands on its call-site node (call-site id + occurrence index inside loops, the many-rows-per-step shape v1 has for loop bodies, runner.py:971-972), so a failed run shows the failing node with its error. Live runs and live edits keep the existing shimmer and glow mechanics. v1 playbooks keep the client-side `buildGraph` path untouched. The interim code + step-list view from plugin/04 is gone for python playbooks. 2026-09-08 (phase 08): the per-occurrence step rows exist as landed — `PlaybookStepRun.step_id = "<id>#<n>"` per effect occurrence (phase 02, pinned by phase 08's parity suite); the Runs tab may show `result` and `format` from `list_runs`.

A container with no call site inside it is not a container — it is part of the surrounding compute node ("collapsed compute nodes between effects", master §2 Canvas). Ids: `<ref>` of a container = the id of the first call site inside it in document order (`if-rows`, `for-s`, `try-send`; a same-kind nested container with the same first site gets `_2`, `_3` — never `#`, which plugin/01 reserves for the per-occurrence key `<id>#<n>` and whose checker collision suffix is `_2`); block ids: the root block is `run`, a `for`/`while`/`try` body block carries its container's node id (`for-s`), `if` branches `if-<ref>-then` / `if-<ref>-else`, handlers `try-<ref>-except-<i>` (1-based), `try-<ref>-finally`; a compute node = `compute-<node id of the next item in its block>`, the trailing one `compute-end-<block id>` (`compute-end-run` for the root block).
