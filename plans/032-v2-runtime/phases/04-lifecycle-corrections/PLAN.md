## Goal
After this phase a python playbook is a first-class row: `Playbook.format` says what it is, the three authoring tools take and echo `format=`, the checker gates python writes the way the compiler gates pblang writes, and the runner dispatches on the column for chat runs, candidate runs and trigger-fired runs. Three agent-facing holes close for BOTH formats: `playbook_propose` saves a candidate (never a live version), an un-coercible input fails at intake naming the input and the expected type, and a compute failure is readable in `playbook_run`'s result, `playbook_status`, `playbook_runs`, the failure digest and fix proposals. A rejected edit keeps its ticket; a green write says `validated: true`. The UI shows a python playbook as code plus the run's step list — no fake graph. v1 playbooks behave as before and the existing suite stays green, except the tests that pin the removed propose-goes-live behaviour (Risks 15), which are adjusted in step 10.
