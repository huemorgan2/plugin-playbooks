This document is the one text the v2 static checker (`plugin_playbooks/v2/checker.py`),
the in-jail shim and segment loop (plans/032 phases 02-03), the dry-run stubs (phase 05)

(Language, Execution model, Properties, Static checker, Error contract, Prompt surface,
Dry run). Values the master left open are marked *(decided here)* and were confirmed
in phase 01's execution summary.

## 1. Shape

A v2 playbook is one plain-Python file with exactly one top-level
`async def run(ctx, inputs)`. Full Python semantics apply inside it: loops,
comprehensions, f-strings, `try`/`except`, ordinary variables. No `state()` ops, no
Jinja, no `collect=` — durability comes from replay (§5, §6).

- The manifest (name, description, when_to_use, inputs schema, triggers) is a separate
  object; code never carries identity, so an edit can never rename a playbook.
- `inputs` is a plain `dict`, typed per the manifest's inputs schema at intake
  (`_coerce_inputs`, runner.py; the loud failure on an un-coercible value is phase 04).
  Read it as `inputs["url"]`; there is no `inputs.url`, no `steps`, no `vars`, no `event`.
- Module level may hold a docstring, whitelisted imports (§8 R4), `def`/`async def`
  helpers and `NAME = <literal>` constants — nothing else, and no classes anywhere.
- `run` may `return` any JSON-serialisable value; it becomes the run's `result`.
- The only stdout an author gets is `await ctx.log(msg)` (§7).

The reference playbook (the master §2 example, verbatim). It passes the checker with no
issue and its call-site ids are `rows`, `s`, `approve`, `send_message` (§7):

```python
async def run(ctx, inputs):
    rows = await ctx.tool("fetch_list", url=inputs["url"])
    good = [r for r in rows["items"] if r["score"] > 3]
    summaries = []
    for r in good:
        s = await ctx.llm(f"Summarize {r['title']}", output={"s": "str"})
        summaries.append(s["s"])
    await ctx.approve(show=summaries)
    await ctx.tool("send_message", to=inputs["owner"], text="\n".join(summaries))
    return {"count": len(summaries)}
```

A second shape the checker admits — a work queue with `while`/`.pop(0)`, a handled
effect failure (`except ctx.ToolError`), a deliberate `raise`, and a fan-out through
`ctx.gather`. Call-site ids: `page`, `summary`, `send_message`:

```python
async def run(ctx, inputs):
    queue = list(inputs["urls"])
    pages = []
    failed = []
    while queue:
        url = queue.pop(0)
        try:
            page = await ctx.tool("fetch_page", url=url, _retry=2)
        except ctx.ToolError as e:
            failed.append({"url": url, "error": str(e)})
            continue
        pages.append(page)
        for link in page.get("links", []):
            if link not in queue and link not in [p["url"] for p in pages]:
                queue.append(link)
    if not pages:
        raise ValueError("nothing fetched: " + ", ".join(f["url"] for f in failed))
    summaries = await ctx.gather(*[
        ctx.llm(f"Summarize {p['text']}", output={"s": "str"}, _id="summary")
        for p in pages
    ])
    report = "\n".join(s["s"] for s in summaries)
    await ctx.tool("send_message", to=inputs["owner"], text=report)
    return {"pages": len(pages), "failed": failed}
```

## 2. Effects

Effects are the ONLY way to touch the world. Every effect is `await`ed (or handed
un-awaited to `ctx.gather`), is called on the name `ctx` only, and is one journal row
per occurrence (§6). Tool names and playbook names are string literals so the tool set
is statically enumerable.

| Effect | Signature | Returns | Raises | Options | Status |
|---|---|---|---|---|---|
| `ctx.tool(name, /, **args)` | `name` a string literal, positional-only (a tool parameter called `name` still works); tool args keyword-only | the parsed tool result, unwrapped (what `_normalize_tool_result` yields) | `ToolError`, `EffectTimeout`, `OutcomeUnknown` | `_id`, `_timeout`, `_retry` | available |
| `ctx.llm(prompt, *, output=None, purpose=None, model=None, system=None)` | `output` is the v1 schema dict | `dict` when `output` is given, else `str` | `EffectError`, `EffectTimeout` | `_id`, `_timeout`, `_retry` | available |
| `ctx.agent(prompt, *, output=None, tools=None)` | same return rule as `ctx.llm`; the transcript is attached to the journal row (phase 03) | `dict` when `output` is given, else `str` | `EffectError`, `EffectTimeout`, `OutcomeUnknown` | `_id`, `_timeout`, `_retry` | available |
| `ctx.subtask(playbook, inputs=None, *, returns=None)` | `playbook` a string literal; `returns` = list of keys picked from the child's return value *(decided here)* | the child's return value (or the picked keys) | `SubtaskFailed`, `EffectTimeout`, `OutcomeUnknown` | `_id`, `_timeout` | available |
| `ctx.gather(*effects)` | arguments are un-awaited effect calls (never a nested gather, a helper coroutine or a plain value); `*[...]` of effect calls allowed | a list of results in argument order | the first failure, raised after all arguments settle | none | available |
| `ctx.approve(*, show)` | `show` required — what the owner sees on the card | `{"approved": True, "request_id": str, "reason": str or None, "decided_by": str or None}` — `request_id` is the approval request id the card was minted under; `reason`/`decided_by` are `None` when rebuilt from a restart-side lookup *(decided here)* | `Rejected`, `ApprovalExpired` | `_id` | available (in-process phase 03; park form phase 07) |
| `ctx.wait_event(name, *, filter=None, timeout)` | `name` a string literal; `timeout` (seconds, the wait bound — distinct from the option `_timeout`) REQUIRED: no unbounded parks | the event payload `dict` | `EventTimeout` | `_id` | not available in this version (phase 07 lifts R10 by adding `"wait_event"` to `DEFAULT_FEATURES`) |
| `ctx.now()` | no arguments | tz-aware UTC `datetime`, journaled as ISO-8601 *(decided here)* | — | `_id` | available |
| `ctx.random()` | no arguments | `float` in `[0.0, 1.0)`, journaled *(decided here)* | — | `_id` | available |
| `ctx.log(msg)` | one argument | `None`; journaled, seq-tagged | — | `_id` | available |
| `ctx.sleep(seconds)` | — | — | — | — | not available in this version (deferred to a separate plan; rejected in every phase, never a stub) |

Rules that apply across the table:

- A journaled value is replayed: a resumed run keeps the `now`/`random`/`llm` value it
  already drew instead of re-rolling. Only an `in_flight` row of a side-effect-free kind
  (`llm`, `now`, `random`, `log`) is re-executed on resume; `tool`/`agent`/`subtask` rows
  found `in_flight` become `timed_out_unknown` and the replaying segment receives
  `OutcomeUnknown` (§6).
- `ctx.gather`: the shim emits all N pending effects in one exit; the host runs them
  concurrently; journal `seq` is assigned in argument order; results come back in
  argument order; the first failure is raised after every argument has settled.
- A CAUGHT effect failure is journaled `failed_handled` and never hoisted onto the run
  status — a handled failure is a green run.
- FAILURE PATH: when the owner wants the run to stop on a failed effect, write it
  explicitly — `try:` around the effect(s), `except ctx.ToolError as e: raise
  ValueError(f"<what> failed: {e}")` naming the item — and say so in the reply. An
  uncaught error also fails the run, but without a message naming what failed; the
  explicit raise is what was asked for. (The v2 skill carries this sentence.)
- `_timeout` is enforced for every kind (phase 02); defaults per kind are in §12.
- Every `ctx.approve` result — in-process, park-resume, dry — has exactly the keys
  `approved`, `request_id`, `reason`, `decided_by` (`APPROVE_RESULT_KEYS`; the dry answer
  adds `dry`). `approval_id` is never an effect-result key: phases 07-08 reserve it for
  the `parked_on` record.

### 2.1 `ctx.llm`

- Signature: `ctx.llm(prompt, *, output=None, purpose=None, model=None, system=None)`;
  `prompt` is a `str`. Host: the v1 `run_llm` facade (`purpose` defaults to
  `"summarization"`, `output` is passed as the answer schema), inside the run's billing
  scope, bounded by `_timeout` (§12 default).
- Returns: a `dict` when `output` is given (a non-dict answer is wrapped as
  `{"_raw": ...}`), else a `str` (a structured answer is JSON-encoded).
- Raises: `EffectError` (no agent injected, facade failure), `EffectTimeout`.
- Journal row: `kind: "llm"`, `name: None`, `args: {prompt, output, purpose, model,
  system}`, `result` the returned value; `cost_cents` when the facade reports a cost.

### 2.2 `ctx.agent`

- Signature: `ctx.agent(prompt, *, output=None, tools=None)`. Host: the v1 `run_turn`
  facade with `memory_write=False`, `conversation_id` = the run's `report_to`, and the
  delegation event feed capturing the turn; the nested-run gate (`active_run_id`) is set
  for the duration, so the turn cannot start another run.
- Returns: same rule as `ctx.llm` (`dict` with `output`, else `str`).
- Raises: `EffectError` (no agent, facade failure, or the facade's `_aborted` answer —
  its `error` text is the message; an aborted turn is never a value), `EffectTimeout`,
  `OutcomeUnknown` (§6 resume rule).
- Journal row: `kind: "agent"`, `name: None`, `args: {prompt, output, tools}`, `result`;
  `transcript` — the delegation-shaped event list (`kind`, `label`, `detail`, `ok`,
  `ts`, `ms`), also on a failed row; `cost_cents` when reported.

### 2.3 `ctx.subtask`

- Signature: `ctx.subtask(playbook, inputs=None, *, returns=None)`; `playbook` a string
  literal, `inputs` a dict. Host: a child `PlaybookRun` started through the runner with
  `trigger: "subtask:<parent run id>"`, `parent_run_id` = the parent, `is_test` inherited,
  driven by the same loop; the parent's row completes when the child's run completes.
  A child whose playbook name is already running in the parent's ancestor chain is
  refused before any child row exists: `EffectError` "would recurse". `_timeout`
  (default unbounded) cancels the child run (row `cancelled`) and raises
  `EffectTimeout` in the parent.
- Returns: the child's `run()` return value; with `returns=[...]` the picked keys of a
  dict value (a non-dict value or a missing key is `SubtaskFailed`).
- Raises: `EffectError` (unknown playbook — `Subtask playbook '<name>' not found` —,
  non-python target, recursion), `SubtaskFailed` (the child ended other than `done`;
  the message names the child run id and its error), `EffectTimeout`, `OutcomeUnknown`.
- Journal row: `kind: "subtask"`, `name` = the playbook name, `args: {inputs, returns}`,
  `result` the (projected) value, `child_run_id` once the child run exists (also on a
  failed or timed-out row).

### 2.4 `ctx.gather`

- Signature: `ctx.gather(*effects)` — un-awaited effect calls only.
- Returns: the list of results in argument order.
- Raises: the first failure in argument order, after every argument has settled; a
  failure the code catches leaves the other rows' outcomes intact.
- Journal rows: none of its own — one row per argument, `seq` in argument order; the
  shim's single `gather` exit lists exactly the pending arguments (§6).

### 2.5 `ctx.approve` (in-process form)

- Signature: `ctx.approve(*, show)`; `show` is what the owner sees (a `str`, or a JSON
  value rendered as text). Host: the approval engine's `request(...)` with
  `kind: "playbook_effect"`, `payload: {run_id, seq, playbook, version}`,
  `requested_by_plugin: "plugin-playbooks"`, `risk_level: "medium"`,
  `conversation_id` = the run's `report_to`, a presentation whose `changes` carry
  `show` as text, and `ttl_seconds` = `_timeout` when given. The effect awaits the
  decision in the run task (the park form is phase 07).
- Returns: `{"approved": True, "request_id", "reason", "decided_by"}` (`APPROVE_RESULT_KEYS`).
- Raises: `Rejected` (`approval <id> rejected: <reason>`) — `ApprovalExpired`
  (`approval <id> expired before a decision (ttl elapsed)`) when the engine reports the
  request `expired`, or, without a lookup, when the decision is the engine's expiry
  shape (`reason == "ttl elapsed"`, `decided_by == "system"`); `EffectError` when no
  approval engine is available or the request itself fails.
- Journal row: `kind: "approve"`, `name: None`, `args: {show}`, `result` the dict above;
  a rejection/expiry is a `failed` row with `error.type` `Rejected`/`ApprovalExpired`.

### 2.6 Caught failures

A failed effect the code catches (`except ctx.ToolError`, `except ctx.EffectError`, ...)
and proceeds past is journaled `failed_handled`: the shim reports the seqs of the
replayed failures it threw into `run()` on its next exit (`handled`), and the host
re-stamps those `failed` rows. Replaying a `failed_handled` row raises the same
exception again, so the same `except` catches it on every segment. A handled failure
never reaches the run status — the run is `done` if `run()` returns.

## 3. Effect options

Options are underscore-prefixed keyword arguments so they can never collide with a real
tool parameter (`http_request(timeout=)` is a tool argument; `_timeout=` is the option).

| Option | Type | Kinds | Meaning |
|---|---|---|---|
| `_id` | `str` literal, unique per call site | every kind except `gather` | the call-site id used in the journal, the trace, the canvas and dry-run `stubs` keys (§7) |
| `_timeout` | `int` or `float` seconds | `tool`, `llm`, `agent`, `subtask` | wall-clock bound for the effect; expiry raises `EffectTimeout`; defaults in §12 |
| `_retry` | `int`, or `{"attempts": int, "backoff": float}` | `tool`, `llm`, `agent` | host-side retry: ONE journal row with an `attempts` list; retries `ToolError`/`EffectTimeout` only — never `OutcomeUnknown`, never `Rejected` |

An unknown `_x` option, a non-literal `_id`, a non-numeric `_timeout`, a malformed
`_retry`, or an option on a kind that does not take it is checker error R16.

## 4. Exceptions

All effect errors derive from `ctx.EffectError` (an `Exception`), so `try`/`except`
around an effect is meaningful:

- `ctx.EffectError` — base class of every catchable effect failure.
  - `ctx.ToolError` — the tool errored or raised.
  - `ctx.EffectTimeout` — `_timeout` expired.
  - `ctx.OutcomeUnknown` — the host lost the outcome (process died mid-effect; §6).
  - `ctx.Rejected` — the owner rejected the approval card.
  - `ctx.ApprovalExpired` — the approval card's `ttl_seconds` elapsed.
  - `ctx.EventTimeout` — `ctx.wait_event`'s `timeout` elapsed.
  - `ctx.SubtaskFailed` — the child playbook failed *(decided here)*.

`ctx.RunCancelled`, `ctx.JournalDivergence` and `ctx.MaxEffectsExceeded` derive from
`BaseException` and cannot be caught: run cancellation (`cancel_run`), a journal that no
longer matches the code path (§5), and the `MAX_EFFECTS` cap (§12) always end the run.
Catching them is checker error R19; a bare `except:` / `except Exception` around an
effect is R18 — catch `ctx.EffectError` or one of its subclasses instead.

## 5. Determinism

"Deterministic" means REPLAYABLE: the code — not an LLM — decides the next step, and a
resumed run retraces the same path to the same effect. It does not forbid randomness or
clocks; it requires every source of variation to be pinned:

- Clock and randomness go through `ctx.now()` / `ctx.random()` so the drawn value is
  journaled and reused on replay (R6, R7).
- The jail runs Python with `-I`, so `PYTHONHASHSEED` from the environment is ignored and
  str/bytes hashes differ per process: iterating a `set` of strings, or a dict built from
  one, orders differently in each segment and breaks replay. The shim therefore runs the
  playbook under a fixed `PYTHONHASHSEED=<per-run seed>` journaled as `hash_seed` in
  entry 0 (phase 02), and the checker warns on set iteration (R22), `hash()` and `id()`
  (R23).
- `JournalDivergence` is raised when a replaying segment asks for an effect that does not
  match the journaled row at that `seq` (kind, id or args differ). Its message lists the
  candidate causes: set iteration, code edited under a running run, non-journaled
  randomness.
- Replay cost is O(effects²) in pure compute, so a run is capped at `MAX_EFFECTS = 200`
  (§12) with a loud `MaxEffectsExceeded` beyond it. R24/R25 warn about shapes that get
  there (more than 40 static call sites, an effect in nested loops).
- `ctx.gather` order is fixed by the argument order (§2), so a fan-out replays identically.

## 6. Journal

`inputs/journal.json` is the ordered list the host writes into the run dir before every
segment and the shim replays from. Entry 0 describes the run; every later entry is one
effect occurrence.

Entry 0:

```text
{seq: 0, kind: "run", hash_seed, inputs, playbook, version, format,
 mode: "real" | "dry", max_effects, started_at, code_sha256}
```

`code_sha256` (phase 06) is the SHA-256 of the source the run started on; a resume
compares it with the pinned version row's code before any jail spawn.

Effect rows:

```text
{seq, kind, id, occurrence, name, args, idempotency_key: "<run_id>:<seq>",
 status: in_flight | done | failed | failed_handled | timed_out_unknown | parked,
 result, error: {type, message}, attempts: [{n, error, ms}], dry: bool,
 started_at, ended_at, ms}
```

- `id` is the checker's call-site id (§7); `occurrence` counts the occurrences of that
  site in this run (loops), so the per-occurrence key is `<id>#<occurrence>` — derived,
  never stored as a separate field. `name` is the literal tool name for `tool` rows
  (the playbook name for `subtask`, phase 03) and `None` for every other kind.
- `args` are the raw arguments with the `_id`/`_timeout`/`_retry` options stripped —
  `vault:` refs are stored unresolved, never the secret.
- The host journals FIRST (`in_flight`) and executes second; the `in_flight` row is
  committed before the handler runs, so a process death between the row and the
  result leaves the row behind. On resume an `in_flight` `tool`/`agent`/`subtask`/
  `approve` row becomes `timed_out_unknown` and the segment receives
  `OutcomeUnknown` — those kinds are never silently re-executed.

Durable journal (phase 06): the live store is the `playbook_journal` table — one row
per entry, primary key `(run_id, seq)`, `run_id` cascading with `playbook_runs`, a
unique index on `idempotency_key`; columns `kind`, `call_site_id` (the entry's `id`),
`occurrence`, `name`, `args` (raw `vault:` refs, never the secret), `idempotency_key`,
`status`, `result`, `error`, `attempts`, `transcript`, `cost_cents`, `child_run_id`,
`dry`, `started_at`, `ended_at`, `ms`. Row 0 is `kind: "run"`, `status: "done"` with
entry 0's fields in `args`. Rows are never deleted on completion (they cascade with the
run row); dry runs never write the table.

Resume (phase 06): `on_server_ready` continues every `running` run that has a row 0
(v1 rows have none and are swept as before) on the exact `playbook_version` it
started on — a missing version row fails the run `VersionMissing`; a version row whose
`code` no longer hashes to `code_sha256` fails it `JournalDivergence` ("code edited
under a run") with no jail spawn. Reconciliation runs in seq order over the run's
`in_flight` rows before the first resumed segment:

- `tool`, `agent`, `subtask`, `approve` → `timed_out_unknown`, `error`
  `{type: "OutcomeUnknown", message: "outcome unknown — the server restarted while effect <id>#<n> was in flight"}`;
  the step row closes `failed` with the same message. `_retry` never re-invokes a lost
  outcome (§3). A child run in flight under a `subtask` row is resumed on its own; the
  parent's row stays unknown.
- `llm`, `now`, `random`, `log` → re-executed by the host from the journaled `args`
  into the SAME row (same `seq`, same `idempotency_key`; fresh `now`/`random` values,
  the same `{"message"}` for `log`), so a `gather` batch keeps its seq alignment.

The replaying segment then raises `ctx.OutcomeUnknown` at the unknown row: caught, the
run goes on and the row keeps `timed_out_unknown` (a handled unknown is not re-stamped
`failed_handled`); uncaught, the run ends with status `timed_out_unknown`,
`error_type: "OutcomeUnknown"` and `error` naming the effect. The ancestor chain for
the subtask cycle guard is rebuilt from `playbook_runs.parent_run_id`; `cancel_run`
works on a resumed run through its task like on any background run.
- `attempts` lists every `_retry` attempt of the row (§3): `_retry=N` means N extra
  attempts after the first; `{"attempts": N, "backoff": b}` the same with backoff
  `min(b * 2**(n-1), 60)` seconds before retry `n` (`b` defaults to 1). A row is
  written once; retries grow its `attempts` list. `ms` is the host wall time of the
  whole row; `attempts[].ms` that of one attempt.
- `now` rows journal the ISO-8601 UTC string and `run()` receives
  `datetime.fromisoformat(result)` on first execution and on replay alike; `random`
  rows journal a `SystemRandom` float; `log` rows carry `{"message"}` in `result`.
- `agent` rows also carry `transcript`, `llm`/`agent` rows `cost_cents` when the facade
  reports one, `subtask` rows `child_run_id` (phase 03, §2.1-2.3); parked rows carry
  `parked_on` (phase 07).
- A row that was `in_flight` when `cancel_run` cancelled the run task is completed
  `failed` with `error.type == "RunCancelled"`. `ctx.RunCancelled` is never raised
  inside `run()`: the jail is one-shot and never sees the cancellation (§4's
  "cannot be caught" holds trivially — no author frame is on the stack).

Envelope — the `input_json` of every `code_run` segment (`inputs` inside the jail):

```text
{playbook, version, source, hash_seed, max_effects, call_sites, journal}
```

`call_sites` is `check(...).summary["call_sites"]` for the saved source, `journal` the
list above; entry 0's `inputs` are the run inputs handed to `run()`.

Segment result — the shim's return value, one `outputs/result.json` per segment,
dispatched on `kind`:

| `kind` | Payload | Host action |
|---|---|---|
| `effect` | `{seq, id: "<id>#<occurrence>", call_site_id, occurrence, effect_kind, name, args, options: {_timeout, _retry}}` | journal `in_flight`, execute, complete/fail the row, re-invoke |
| `gather` | `{seq, effects: [effect payloads]}` (phase 03 emits it) | journal every effect in argument order, run them concurrently, re-invoke |
| `return` | `{value}` (JSON-serializable; else `kind: error` with `ResultNotSerializable`) | run `done` |
| `error` | the §7 runtime error payload | run `failed` with the four run columns |

`outputs/progress.json` `{seq, phase: replaying | compute | effect_exit}` is written
alongside; it reaches the host only through a storage provider, so a segment timeout
names the last journaled effect and refines it with `phase` when present.

## 7. Error contract

Checker issues, all at once, each as:

```text
{line, col, source_line, message, expected, example_fix, code, severity}
```

- `line` is 1-based and equals the saved code's line (the code is parsed under the stable
  filename `playbook:<name>@v<N>` with line offset 0 — no shim prefix, no wrapper), so a
  traceback line IS the editor line and IS the line the agent copies into `old=`. The
  shim must `compile()` the saved source from a string under the same filename; the
  jail's own wrapper would shift lines by 5.
- `col` is 0-based; `source_line` is `code.splitlines()[line - 1]` (empty when `line`
  is 0 — an issue with no anchor, such as a missing `run`).
- `severity` is `"error"` (blocks the save) or `"warning"` (rides along); `ok` on the
  result means no error-severity issue.
- `example_fix` is a concrete replacement, never advice.

Call-site ids (`summary.call_sites[].id`; journal `id`; canvas `step-<id>`; dry-run
`stubs` keys `<id>#<n>`): the `_id=` literal when given; else the assignment target when
the awaited call is the value of `name = await ctx.…` (a plain name); else the literal
tool name for `ctx.tool` or playbook name for `ctx.subtask`; else the effect kind
(`approve`, `llm`, `now`, …). A later site whose derived id repeats an earlier one is
suffixed `_2`, `_3` … in document order and gets warning R16b. The suffix is never `#`:
`<id>#<n>` is the per-occurrence key.

Runtime errors: the shim catches everything raised from `run()`, silences stdout, and
returns `kind: error` in `outputs/result.json` (§6 — one result file per segment):

```text
{kind: "error", error_type, message, traceback (frames filtered to the playbook filename),
 playbook_line, last_completed_effect: {seq, id: "<id>#<occurrence>", kind},
 locals_preview (repr <= 200 chars per value, vault refs masked)}
```

`outputs/progress.json` `{seq, phase}` is written before every effect exit so a segment
timeout names the last effect reached ("segment 8 timed out (60s) after effect
fetch_page#1, in pure compute"). The host persists `error`, `error_type`, `traceback`, `failed_at` on the run
and surfaces a one-line failed result in `playbook_run`:

```text
line 7: rows['items'] → KeyError: 'items' after effect fetch#1
```

(`line <n>: <source line> → <error_type>: <message> after effect <id>#<occurrence>`;
"before any effect" when no effect completed; no `line <n>:` prefix when no playbook
frame is on the stack. `SegmentTimeout` and `ShimFailure` are host-side error types with
no playbook frame.)

`failure_signature` keys on (playbook, failed line or effect id, error head) so compute
failures dedupe. `print` is rejected (R8); `ctx.log` is the only author output.

## 8. Checker rules

`plugin_playbooks.v2.checker.check(code, *, name, version, inputs_schema=None,
tool_names=None, features=DEFAULT_FEATURES)` runs every rule and returns every issue.
Codes and severities are `checker.RULES`. R1 short-circuits; everything else accumulates.

| Code | Severity | Rule | Fix |
|---|---|---|---|
| `v2-syntax` | error | R1 — the code does not parse; one issue at the parser's line/col, nothing else runs | fix the syntax |
| `v2-entry-point` | error | R2 — exactly one top-level `async def run(ctx, inputs)`: missing, duplicate, sync `def`, other parameters, defaults, `*args`/`**kw`, or `yield` inside | `async def run(ctx, inputs):` |
| `v2-top-level` | error | R3 — a module-level statement other than a docstring, whitelisted import, `def`/`async def` helper or `NAME = <literal>`; any `class` | move the code into `run` or a helper |
| `v2-import` | error | R4 — module not in the whitelist (`json re math datetime textwrap itertools collections functools operator string decimal fractions statistics typing dataclasses enum base64 hashlib html difflib heapq bisect copy unicodedata`); `time`/`random`/`uuid`/`secrets`/`asyncio` steer to the ctx effect; I/O modules steer to `ctx.tool` | delete the import; use the ctx effect |
| `v2-banned-name` | error | R5 — calls to `open exec eval compile __import__ input breakpoint globals locals vars exit quit help`; access to `__class__ __dict__ __globals__ __builtins__ __subclasses__` | use `ctx.tool` for data; plain data access |
| `v2-use-ctx-now` | error | R6 — `datetime.now/utcnow/today`, `date.today`, `time.time/monotonic/perf_counter` | `now = await ctx.now()` |
| `v2-use-ctx-random` | error | R7 — any `random.`/`uuid.`/`secrets.` call | `r = await ctx.random()` |
| `v2-use-ctx-log` | error | R8 — `print(` | `await ctx.log(msg)` |
| `v2-use-ctx-gather` | error | R9 — `asyncio.gather/create_task/wait/as_completed` | `await ctx.gather(...)` |
| `v2-effect-unavailable` | error | R10 — `ctx.sleep` (always), `ctx.wait_event` unless `"wait_event"` is in `features`, `asyncio.sleep`, `time.sleep`; the message says "not available in this version" | remove the call |
| `v2-unknown-ctx-attr` | error | R11 — `ctx.<x>` not an effect, an exception or an uncatchable; carries a did-you-mean | the suggested name |
| `v2-effect-not-on-ctx` | error | R12 — a bare `tool( llm( agent( approve( subtask( gather( wait_event( code( loop( if_( parallel( state( halt(` or `playbook(` call, or an effect name called on a receiver other than `ctx` | `await ctx.<effect>(...)` |
| `v2-missing-await` | error | R13 — an effect call that is not awaited, not a direct/starred `ctx.gather` argument, and not an element of a list/comprehension whose only use is `*name` inside `ctx.gather` | `result = await ctx.<effect>(...)` |
| `v2-tool-name-literal` | error | R14 — `ctx.tool`/`ctx.subtask`/`ctx.wait_event` first argument missing or not a string literal; extra positional arguments on `ctx.tool` | `ctx.tool("name", key=value)` |
| `v2-unknown-kwarg` | error | R15 — an argument outside the signature table (§2); a missing required argument (`prompt`, `show`, `timeout`, `msg`); `**` splat on anything but `ctx.tool` | the accepted names are in `expected` |
| `v2-option` | error | R16 — unknown `_x`; `_id` not a string literal; `_timeout` not a number; `_retry` not int/dict; an option on a kind that does not take it (§3) | see §3 |
| `v2-duplicate-call-site-id` | warning | R16b — two call sites resolve to the same id (§7); the later one is suffixed `_2`, `_3` … | give each site its own `_id=` |
| `v2-unknown-tool` | error | R17 — only when `tool_names` is given: the literal is not in the set | a registered tool name |
| `v2-broad-except` | error | R18 — `except:` / `except Exception` / `except BaseException` whose `try` body contains an effect | `except ctx.EffectError` (or `ctx.ToolError` …) |
| `v2-uncatchable` | error | R19 — `except ctx.RunCancelled` / `ctx.JournalDivergence` / `ctx.MaxEffectsExceeded` | catch `ctx.EffectError` instead |
| `v2-inputs-attr` | error | R20 — `inputs.<name>` (dict methods excepted); the bare names `steps`, `vars`, `event` when not bound locally | `inputs["name"]`; ordinary variables |
| `v2-unknown-input` | warning | R21 — only with `inputs_schema`: `inputs["k"]` / `inputs.get("k")` with `k` not in `properties` | a declared key |
| `v2-set-iteration` | warning | R22 — `for`/comprehension/`join`/`list(...)` over a set display, set comprehension, `set(...)` call, or a name bound to one in the same function | `sorted(...)` |
| `v2-nondeterministic-builtin` | warning | R23 — `hash(`, `id(` | a value derived from the data |
| `v2-too-many-call-sites` | warning | R24 — more than 40 static effect call sites | split with `ctx.subtask` or loop over data |
| `v2-effect-in-nested-loops` | warning | R25 — an effect at loop depth 2 or more; the message names `MAX_EFFECTS = 200` | flatten the loops |
| `v2-gather-args` | error | R30 — a `ctx.gather` argument that is not an effect call (a nested gather, a helper coroutine, an awaited value) | `ctx.gather(ctx.tool(...), ...)` |
| `v2-async-construct` | error | R29 — `async for` / `async with` | a plain `for`; effects via `await ctx.…` |
| `monolithic-playbook` | error | R26 — exactly one non-delivery effect in `run`, it is `ctx.llm`/`ctx.agent`, and its prompt has a quantifier/sequence/multi-op-I/O or interpolates a collection (delivery = `ctx.tool("send_chat_message", …)`) | decompose: fetch → loop → reduce → deliver |
| `compound-leaf` | warning | R26 — a non-looped `ctx.llm`/`ctx.agent` prompt with a quantifier, a sequence, or 2+ operations | one operation per iteration |
| `agent-does-work` | warning | R26 — `ctx.agent` with I/O verbs and no judgment cue | do the work with `ctx.tool`; reserve `ctx.agent` for decisions |
| `context-economy` | warning | R26 — a non-looped `ctx.llm`/`ctx.agent` whose f-string interpolates an array-typed input, a whole `ctx.tool` result, or a subscript/attribute ending in a collection word (`messages items results rows records data emails entries files`) | loop, summarize one item per iteration, collect |
| `v2-format-mismatch` | error | R27 — from `resolve_format` (§9): an explicit `format` that disagrees with the sniff; line 1, col 0 | pass the sniffed format |
| `v2-format-unknown` | error | R27 — from `resolve_format` (§9): `format` not one of `pblang`, `python`; line 1, col 0 | `format="python"` |

Prompt text for the R26 lints is the string constant or the constant parts of an
f-string; the marker tables are the v1 ones (`validation.py`), so the four codes fire on
the same phrases in both languages.

`check()` also returns `summary` — what phase 04 stores as the playbook's `definition`:

```text
{format: "python", tools: [sorted literal tool names], subtasks: [sorted playbook names],
 call_sites: [{id, kind, line, col, tool | None, playbook | None, loop_depth, in_try}],
 inputs_read: [sorted keys], imports: [sorted modules]}
```

## 9. Format selection

Format selection is explicit, never a guess (`checker.resolve_format(explicit, code,
stored=None, default="python")`):

1. `explicit` not in `FORMATS = ("pblang", "python")` → `(None, v2-format-unknown)`.
2. `explicit` given, the sniff is not `None` and differs → `(explicit, v2-format-mismatch)`.
3. `explicit` given → `explicit`.
4. Else the sniff: `^\s*async def run\(` (multiline) → `python`; else `^\s*playbook\(` →
   `pblang`; python wins when both match (a python string mentioning `playbook(` is
   still python).
5. Else `stored` — the playbook's stored format (edit).
6. Else `default` — `python` (propose).

`format` is echoed in every tool result (phase 04). The `LANGUAGE_MINIREF` /
`LANGUAGE_CHEATSHEET` riders ride only on pblang paths.

## 10. Dry run

A dry run is the SAME segment loop with `mode="dry"` (phase 05): the host answers every
effect from `stubs` — keyed per occurrence `<call-site id>#<n>` (`fetch#1`, `summary#3`)
— or, when no stub matches, with a `DryStub`; every journal row carries `dry: true`;
nothing executes; no run rows are written. Real control flow runs.

- A `DryStub` truth-tests `True` and iterates ONCE, so every branch and loop body is
  exercised (v1's falsy stubs skipped every loop and `if`). Reading data a stub does not
  have raises `DryStubError` naming the effect id, the access path and the `stubs` key
  that would satisfy it — never a Python traceback.
- Placeholder semantics *(decided here)*: key/attribute access returns a nested
  placeholder (path `.key` / `[n]`); with a declared output schema (`ctx.llm(output=)`,
  `ctx.agent(output=)`, `ctx.subtask(returns=)`) a declared key returns its typed sample
  (`str` → `"<dry:<id>#<n>.<path>>"`, `int` → `0`, `float` → `0.0`, `bool` → `True`) and an
  undeclared key raises `DryStubError`; `str()` is `<dry:<id>#<n>.<path>>`, which is what a
  placeholder passed into a later effect's arguments journals as; `<`/`>` compare `True`,
  `in` is `True`, any two placeholders are equal and a placeholder equals no real value
  (so `link not in seen` terminates); arithmetic, `int()`, `float()` raise `DryStubError`.
  A provided stub is wrapped the same way: reading a key it lacks raises `DryStubError`
  naming the stubs key.
- `stubs` key shape: `{"<id>#<n>": <value>}` answers one occurrence, `{"<id>": <value>}`
  every occurrence of that call site; `<id>` is the checker's call-site id (§7) — the
  `_id=` literal, else the assignment target, else the literal tool/playbook name, else
  the kind — never the tool name of an assigned site. The per-occurrence key wins.
- Per kind: `tool`/`llm`/`agent`/`subtask` → the stub; `approve` → `APPROVE_RESULT_KEYS`
  plus `dry: True` (`request_id` is `dry:<id>#<n>`, `reason`/`decided_by` `None`);
  `wait_event` → the stub payload, or `EventTimeout` when the stub says so; `now` →
  `2000-01-01T00:00:00+00:00`; `random` → the `random.Random(0)` sequence; `log` →
  `{"message"}` (fixed seeds: two dry runs of one version agree).
- The journal row of a dry effect carries `dry: true`, `stubbed`, `stub_key`, `schema`
  and `effect` (`"<id>#<n>"`); the jail rebuilds the placeholder or wraps the stub from
  them in `_pb_decode_result`. Entry 0 has `mode: "dry"`.
- The result reports `unreached_call_sites` (the checker's static `call_sites` minus the
  ids the journal reached) and status `simulated` or `simulated_nothing_exercised` (zero
  effects reached, e.g. an early return or an exception before the first effect).
- Result keys: `status`, `dry_run: true`, `banner`, `steps_ran` (`{"<id>#<n>": {kind,
  args, result, stubbed}}`), `unreached_call_sites` (`[{id, kind, line}]`), `journal`,
  `result` (the `run()` return value, placeholders as their string form), `error` /
  `error_type` (`null` on a clean run; a `DryStubError` surfaces as the §7 one-liner and
  `error_type: "DryStubError"`, never a traceback), plus `format`, `tested_version`,
  `is_candidate` from `playbook_dry_run`. An un-coercible input is rejected before
  segment 1 with `{"status": "rejected", "error", "input", "expected", "dry_run": true}`.
- `playbook_dry_run(name, version=candidate | N, stubs=…, stubs_from_run=<run_id>)`
  (phase 08) takes the per-occurrence stubs from a recorded run's journal so a fix is
  exercised against the exact inputs that broke it.
- A dry run is labelled simulated and never satisfies the `test_run` publish gate.

## 11. What runs where

| Where | What |
|---|---|
| Static (host, no execution) | `check()` — parse, rules, `summary`; `resolve_format` |
| Jail (one-shot per segment) | the shim (`SHIM_SOURCE`, the constant `code` argument of `code_run`) re-execs itself under `PYTHONHASHSEED=<hash_seed>` (option A), compiles the saved source from the envelope under `playbook:<name>@v<N>`, replays the envelope's `journal`, runs `run()` until the first effect with no journal row, writes ONE `outputs/result.json` with `kind: effect \| gather \| return \| error` (§6) and exits 0 |
| Host (segment loop) | journals `in_flight`, executes the effect (tool via the registry with vault resolution on a copy; llm/agent via the plugin agent facade; subtask as a child run), overwrites the row, emits the step events, re-invokes the jail |
| Parked (phase 07) | `approve` (park form) and `wait_event` park the run; `approval.decided` / the event bus resume the segment loop; `on_server_ready` reconciles |

## 12. Constants

From `plugin_playbooks/v2/__init__.py`:

- `MAX_EFFECTS = 200` — effects per run; `MaxEffectsExceeded` beyond it.
- `DEFAULT_TIMEOUTS = {"tool": 120, "llm": 300, "agent": 900, "subtask": None}` — the
  `_timeout` default per kind in seconds; `None` = unbounded (subtask is bounded by
  phase 07's `max_duration`).
- `FORMATS = ("pblang", "python")`.
- `AVAILABLE_EFFECTS` = tool, llm, agent, subtask, gather, approve, now, random, log.
- `UNAVAILABLE_EFFECTS` = wait_event, sleep → "not available in this version".
- `DEFAULT_FEATURES = frozenset()` — phase 07 adds `"wait_event"`.
- `CTX_EXCEPTIONS`, `CTX_UNCATCHABLE` — §4.
- `APPROVE_RESULT_KEYS` = approved, request_id, reason, decided_by — §2.
- Checker thresholds: 40 call sites (R24), loop depth 2 (R25).
